Evidence before acknowledgment

The Rust core validates changes and syncs a checksummed journal before transport advances its acknowledgment. Partial trailing frames are recoverable; complete corrupt frames are rejected.

decode → append → fsync → ACK
03

A case you can run

Backward row lineage keeps whole transactions and their companion writes. Export SQL for a fresh schema, then reproduce the behavior through a real replica.

selected row → lineage → SQL
Why not just compare tables?

A table diff answers which values disagree. Rowglass adds the committed history that produced a row and a replayable workload. It needs a recording in place before the incident and uses memory proportional to the reconstructed state. For a one-time reconciliation without history, a table-diff tool is the simpler fit.

Read the documented behavior ↗
REPLAY CONTRACT

Small enough to investigate

The slice keeps whole transactions connected through row keys. It reconstructs row changes, not the original application statements, foreign keys or triggers. It is not a claim of a mathematically minimal failing case.

Inspect the replay manifest ↗
MEASURED COST

Correctness before scale claims

Full-state reconstruction and comparison are currently in memory. The recorder uses one fsync per committed transaction. Throughput depends heavily on transaction size and storage latency.

Inspect recorded measurements ↗
Supported scope and important limits +

PostgreSQL protocol v1, UTF-8 text tuples, regular tables with explicit primary keys. Exact numeric, JSON, boolean, bytes, timestamps and common scalar types are canonicalized; unsupported values remain unverifiable. Failover, incomplete bootstrap and selected schema changes require a new recording or explicit intervention. Transactions above 64 MiB are rejected before acknowledgment. Visible maximum-version conflicts are rejected; background merges may already have erased older versions. Evidence may contain source values, so review it before sharing.
